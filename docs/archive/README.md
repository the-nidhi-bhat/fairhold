# Archived reports

These are the historical QA summaries, release verdicts and session-state documents from earlier
FairHold sprints. They are kept for provenance — they record what was verified at the time and
which gaps were open then.

They are **not** the current state of the project. For the live release record use:

| Current document | Purpose |
| --- | --- |
| [RELEASE_REPORT.md](../RELEASE_REPORT.md) | Final release: commit, Vercel deployment, test results, judge journey, manual actions. |
| [../README.md](../README.md) | Primary project explanation and documentation index. |
| [../docs/STATE.md](../STATE.md) | Current session state. |
| [../docs/release/](../release/) | Per-phase audit records from the release execution. |

## Contents

| File | What it records |
| --- | --- |
| `QA_REPORT.md` | Verification evidence and the acceptance matrix from the QA sprint. |
| `FINAL_RELEASE_REPORT.md` | Evidence-based release report and verdicts for the previous release candidate. |
| `FINAL_REMAINING_WORK.md` | Gap matrix of every remaining item, priority and blocker at that point. |
| `HANDOFF.md` | Session handoff — state, blockers and next actions. |
| `TASKS.md` | Task list as it stood. |
| `DECISIONS.md` | Approved architectural decisions with rationale. |
| `RELEASE_CHECKLIST.md` | Release acceptance checklist. |
| `FAIRHOLD_STATE.md` | Compact project state snapshot. |
| `DEMO.md` | Superseded short demo note; use [../DEMO_GUIDE.md](../DEMO_GUIDE.md) instead. |

Figures inside these documents reflect the sprint in which they were written and are not
guaranteed to match the current build.
